# Local Flow Lens playground

[Open the hosted preview](https://footprintjs.github.io/explainable-ui/local-playground/).
GitHub Pages builds both this preview and the existing gallery from `main`.
Or [open the isometric view](https://footprintjs.github.io/explainable-ui/local-playground/?look=isometric)
with Paper styling and Details beside the chart.

Seven real FootprintJS executions presented in the current `ExplainableShell`:

- **Simple:** follow a sequence of recorded steps and state changes.
- **Parallel:** compare branches within one recorded workflow.
- **Loop:** inspect repeated execution along the same chart.
- **Subflows:** explore native nested workflows as group boxes or drill cards.
- **Pricing:** trace an unexpected price back through its recorded inputs.
- **Shipping:** follow an empty rates result into the manual-review branch.
- **Retry:** inspect the recorded attempts and recovery.

The example reads `recordings.json`, generated by running actual workflows. It restores the serialized overlay maps once and passes the complete matching recording cohort to the shell. Vite aliases the public `footprint-explainable-ui` and `footprint-explainable-ui/flowchart` imports to this repository's source, so the preview shows the current implementation.

Use **Node 22.12+ or 24**. From the repository root, install the repository dependencies and start the preview:

```sh
npm install
./examples/local-playground/start.command
```

The bundled recordings are ready to replay; no generator installation or workflow execution is needed to view them. To generate or refresh them separately:

```sh
npm install --prefix examples/local-playground
npm run build
npm run record --prefix examples/local-playground
```

Open <http://127.0.0.1:5314> and keep the Terminal window open. The server binds only to loopback and requires that exact port to be free. The equivalent Vite command is `npx vite --config examples/local-playground/vite.config.ts`.

The normal generator installation pins **FootprintJS 12.2.0** for legacy compatibility. The bundled recordings currently use the unreleased engine source with canonical nested-read capture, so Backtrack can connect `total = 35` to the recorded Items `30` and Delivery `5` writes. The badge explicitly says **source build**, and `sourceBuild` metadata identifies the engine and record-layer revisions. This does not claim the option is available in the published engine. The repository's older engine pin remains the compatibility-test baseline.

To regenerate those precise recordings, first build the coordinated FootprintJS and Foottrace source changes, with that engine checkout using the matching Foottrace build, then run:

```sh
FOOTPRINT_ENGINE_CHECKOUT=/path/to/footPrint npm run record --prefix examples/local-playground
```

This override loads only the engine's built public entry points and enables `nestedReadTracking`. Without it, the normal pinned-package command retains legacy read capture. Updating the viewer cannot add missing reads to an older recording. Recorded read prefixes describe prior state usage; they do not prove expression-level derivation, and parent/container reads without exact writers remain unresolved.

Select a scenario to inspect it manually. **Replay from start** remounts that scenario's shell with autoplay enabled; theme changes keep the existing cursor and shell instance. Pause, scrubbing, tracing, and other manual navigation retain the shell's normal autoplay interruption behavior. Reduced-motion preferences are respected by the shell.

The preview fills one viewport. Scenarios scroll in their own sidebar (a horizontal strip on narrow screens), while the workbench stays in view. **Outcome & instructions** and **Display options** are closed initially; expand either to read or adjust it without scrolling the whole page.

Use **Chart layout** to compare **Default**, **Straight trunk** and **Isometric** layouts. **Outer workflow box** adds or removes the surrounding workflow container. Each native subflow has a checkbox: checked renders a group box, unchecked renders a drill card. The initial view uses drill cards and no outer box. **All groups** and **Clear groups** select or clear the active scenario's native subflow IDs; the renderer applies those selections only at the current drill level. Group boxes expand sibling subflows at that level; drill into a nested subflow to explore deeper levels. Workflows without native subflows explain that limitation while still allowing the outer box. Group choices are remembered separately for each scenario.

**Try isometric view** is a shortcut to the Isometric layout, Paper theme and default **Details beside the chart** arrangement. It changes only these presentation choices, keeping the current recording, stage and replay cursor. The direct `?look=isometric` link initializes the same choices for sharing; the plain preview URL still starts with Standard, Default layout and the existing Details arrangement. Node icons remain Custom SVG by default in both views.

The isometric example uses fixed-angle SVG illustrations to add depth to the same recorded workflow. Labels stay upright; there is no orbit camera. Illustrations do not assert infrastructure resources, deployment state or relationships beyond the supplied recording. Developer, Commentary and Timeline continue to inspect the same selection and replay cursor; use **Lens arrangement** to choose the panels shown.

Layout, grouping and theme changes update the memoized chart renderer without remounting the shell or resetting its cursor. The chart integration uses the shell's existing `renderFlowchart` prop; no library API changes are required.

**Lens theme → Paper** applies a paper-and-pastel palette, thin node outlines and small offset shadows inspired by the [Designed to Scale reference](https://designed-to-scale.vercel.app/#/design-chat/12). The existing light/dark toggle selects `paperLight` or `paperDark`. The surrounding preview and the Lens use the same exported tokens. Standard, Forest and Graphite remain available, and Standard remains the initial choice.

Paper presets and `tokens.nodes` are unreleased source additions, not part of the published 0.45.0 package yet.

Consumers can use the preset directly, without the preview:

```tsx
import { ExplainableShell, paperLight } from "footprint-explainable-ui";

<ExplainableShell
  runtimeSnapshot={snapshot}
  traceGraph={graph}
  theme={{ mode: "light", tokens: paperLight }}
/>;
```

The optional `tokens.nodes` fields control chart-card paint: `borderColor`, `borderWidth`, `borderStyle`, `radius`, `shadow`, `shapeShadow`, `badgeShadow`, `pulseOpacity` and `groupStatusDisplay`. They can also be supplied as a partial override on another palette. Omitted fields retain the existing node appearance, including its per-state styling.

`radius` and `borderStyle` apply to rectangular, pill and group cards; decisions retain their diamond shape. `shadow` uses box-shadow syntax. For clipped decisions, `shapeShadow` takes a CSS filter value such as `"drop-shadow(2px 3px 0 #35332f)"` or `"none"`; drop shadows do not accept spread or `inset`. `groupStatusDisplay` defaults to `"none"`; Paper uses `"inline-flex"` to show a small Selected / Visited / Failed group-header cue alongside its fixed dark outlines. These cues reflect the shared cursor and recorded state.

Changing the theme changes presentation; it keeps the recording, selection and replay cursor. Paper can style any chart layout. The separate Isometric layout supplies the illustrated geometry.

**Node icons** compares the saved recording's icon names, the library's built-in icons and custom inline SVG icons on the actual execution nodes. Custom SVG icons are selected initially. The preview imports the [public consumer example](../node-icons/README.md); the display graph is decorated on a copy, keeping the saved recording, node IDs, runtime overlay and execution cursor intact. Group headers and pill nodes retain their own separate icon mechanisms.

The **Straight trunk** alternative subscribes to rendered node measurements through the public xyflow store hook and passes the same measured footprints to its layout and snap resolver. **Default** retains the library's measured content-size layout pipeline. Neither mode forces an arbitrary card size. Repeated subflow labels show their distinct mount paths beside the checkboxes so each recorded instance can be selected separately.

Optional static build:

```sh
npx vite build --config examples/local-playground/vite.config.ts
```

The output goes to `demo-dist/local-playground` at the repository root. The viewer itself reads the saved recordings; only regeneration needs the example's FootprintJS dependency. To check the example's TypeScript, run `npm run typecheck --prefix examples/local-playground`.

The workflow services are local simulations. Playback moves through a saved recording; regenerate the recordings to execute the workflows again.
