# Shared React controller example

This source example targets the **next library release**. The published `1.0.1` package does not yet provide these controller exports. The repository's Vite aliases resolve public package imports to this checkout for development; this example is not a published-package verification.

Run from the repository after its normal dependency setup:

```
npm exec -- vite --config examples/headless-controller/vite.config.ts
```

Open `http://127.0.0.1:5318/`. The port is strict and never uses port 5314. A later static build uses the separate `demo-dist/headless-controller` directory. This task does not install dependencies or start a server automatically.

`main.tsx` creates two stable `RecordingSource` objects outside React rendering and one `LensControllerProvider`. A small outer component selects the active recording and owns the presentation options; it does not recreate a source when a control changes. Selecting another recording is a run replacement. The creator disposes both sources after all consumers unmount. The plain custom transport and evidence summary read `useLensController()`. The optional default `ExplainableShell` is a sibling under that same provider; it receives presentation props only. Recording/source, playback, automatic playback and progressive-rendering options belong to the provider. Supplying conflicting ownership props to an inner Shell is refused, rather than creating another owner.

Turn on **Show bound transport and Commentary** to mount `LensReplayControls` and `CommentaryPanel` directly under the same provider, without another Shell or provider. The bound transport reuses the existing clock and Backtrack policy; Commentary uses the current recorded narrative, scope and cursor. Turn off the Shell to try these surfaces on their own. `recordingStatus` supplies data-only waiting/empty/ready/error state and an optional fixed reason; this example shows that status in its custom summary. A host chooses its own placeholders and refusal presentation.

The provider receives `controller-options.json`: a normal visible range, `log-duration` scale and a 700 ms reading interval. Controls let you choose equal, linear-duration or log-duration geometry, and normal-thumb or segmented stock presentation. The custom thumb stays a native input; its `0..1` coordinate comes from `controller.replayAxis.positionAt(index)` and maps back through `indexAt(position)` before calling `scrubTo`. This is the same axis as the bound stock transport, not another cursor. `previous/next`, and Home/End with `scrubTo`, keep keyboard movement on exact semantic stages and Backtrack stops. `selectIndex` and exact `selectStage(runtimeStageId)` remain explicit context-selection commands, independent of hidden transport controls. No controlled numeric cursor API is introduced.

The weighted geometry uses supplied `durationMs`: linear weights use the duration, while logarithmic weights use `log1p(durationMs)`. Weights are normalized by the largest transformed duration, with a small geometric floor to keep every stage selectable. Zero/default or unavailable timing does not establish elapsed time; the axis discloses those entries and any raised weights. With no positive timing it falls back to equal spacing. These are widths in a stage sequence, not a wall-clock timeline or a reconstruction of parallel overlap. The 700 ms replay interval is separately configured reading pace.

`ReplayAxis` exposes frozen weights, segment centers, native-input positions and timing-availability counts. Axis preparation is O(n) per new immutable snapshots array/scale, cached across cursor movement; `positionAt` is O(1), and `indexAt` uses O(log n) lookup for pointer coordinates. This does not make all recording parsing or chart layout constant-time. Existing recording sources batch ready visual publication; this example only reads existing recordings and collects no new data.

Select **Combine**, then use **Backtrack total** from the newly rendered Writes list. It uses that current model's admitted `traceTarget`. Follow the recorded amount ingredients to Items (30) and Delivery (5) and their recorded inputs (10, 3, 5). The summary shows the Backtrack return destination and exposes the controller's return action. Hide/remount the standard Shell during playback or tracing to see that the provider outlives a presenter. React state inside the presenter, such as DOM focus or panel expansion, is still presentation-owned.

`recording.json` copies the existing dataset's `parallel` scenario, recorded by the released engine 13.0.0 and Foottrace 2.0.0. Its stage durations are zero/default, so the weighted axis honestly reports equal-spacing fallback. `recording-retry.json` copies the separate `retry` scenario from that same native dataset, including its original Metrics recorder payload (durations 0, 64, 0 ms). Choose **Recorded retry timings**, then **Segments**, to see genuine measured widths and partial-timing disclosure. With only one positive timing, linear and logarithmic normalization produce the same relative widths in this particular fixture. Retry-specific instructions replace the total 35 instructions; no retry is executed here. Only these two small scenarios are copied, not the entire seven-workflow bundle.

Both files retain producer versions/integrities and source scenario/hash information. Imported JSON needs a TypeScript boundary assertion because JSON does not retain branded stage IDs or enum literals; `createRecordingSource` still admits and copies the supplied data at runtime. No execution, measurement, timestamp, history or causal explanation was invented for the example. Values shown in the summary use admitted Activity previews and their availability labels. Unknown data stays unknown.

For an application or agent bridge, first select an exact **recorded** runtime stage. Wait for React to deliver a fresh model whose selected stage/activity identity matches the request. Then choose a target from that model's current reads/writes and call `backtrack(target)`. Do not retain targets across a run/scope change or construct addresses from labels. Likewise, respond to the current `visitChoice` with `chooseInvocation` using one of its supplied runtime IDs. These commands navigate supplied recording evidence; they do not execute or re-execute a workflow.

The controller is **React-headless**: it supplies data and commands without rendering a chart, theme, surface or focus owner. It is not a framework-independent store. Render only the custom children to use no default UI, or compose the standard Shell for its chart, accessible panels and focus behavior. A custom presenter owns its own keyboard/focus/ARIA and unknown/loading presentation.

The hosted example is built after the gallery into its own child directory. CI checks its strict types and build; the separate packed headless-consumer gate verifies actual public entry points. Source aliases in this development example are not a substitute for those package checks. Infrastructure hardware drawings remain in the separate consumer-owned deployment-shapes example; the library does not add a built-in hardware symbol set.
